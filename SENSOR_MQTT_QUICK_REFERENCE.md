# SecureBox — Sensors, MQTT, TLS Quick Reference

## Sensor interfaces

| Sensor | Interface | BeagleY-AI pins | Measurements |
|---|---|---|---|
| BMP280 | I2C | SDA = physical pin 3, SCL = physical pin 5, VCC = 3.3 V, GND = GND | Temperature and pressure. No humidity. |
| BME280 | I2C | SDA = physical pin 3, SCL = physical pin 5, VCC = 3.3 V, GND = GND | Temperature, pressure, and humidity. |
| HC-SR04 ultrasonic sensor | Digital GPIO pulses | TRIG = physical pin 11, ECHO = physical pin 13; VCC = 5 V; GND = GND | Distance. One trigger pulse starts measurement; echo pulse width is converted to distance. ECHO must use a 5 V to 3.3 V divider. |
| Digital vibration sensor/module | Digital GPIO input | OUT/DO = physical pin 15; VCC depends on module; GND = GND | Movement detected or clear. Usually powered at 3.3 V; verify the module output is 3.3 V compatible. |

BMP280 current address: `0x77`. Linux IIO device name: `bmp280`.

## HC-SR04 ultrasonic sensor

- Interface: GPIO timing, not I2C, SPI, or UART.
- Beagle pins: TRIG `P11`/line offset `8`; ECHO `P13`/line offset `33`.
- Power: `VCC` is 5 V; `GND` is common ground.
- Logic: TRIG is sent from Beagle; its output is safe at 3.3 V. The HC-SR04 ECHO output is 5 V and must be reduced to a maximum safe 3.3 V for the Beagle GPIO input.
- Recommended divider: `ECHO → 2 kΩ → GPIO`, then `3.3 kΩ → GND`.
- Measurement method: hold TRIG high for about 10 µs, then measure the width of the ECHO high pulse. Distance roughly equals `pulse_width_us / 58` centimetres.
- Linux implementation: values are measured using libgpiod GPIO lines and Python timing.

## Digital vibration sensor

- Interface: single-wire digital GPIO.
- Beagle pin: `OUT/DO` to physical pin 15; Beagle line offset `41`, controller `main_gpio0`.
- Power: use 3.3 V only if the module supports it, as the Beagle GPIO pins are 3.3 V logic.
- Output interpretation: configured active level is `1`; an active HIGH makes `vibration = true/detected`. If your module output is LOW when active, change `VIBRATION_ACTIVE_LEVEL` to `0`.
- No pull-up or pull-down resistor is normally needed when the breakout includes a defined DO output and the module is documented for 3.3 V operation. Use the board module's onboard resistor/network as specified.
- Linux implementation: libgpiod reads the digital input periodically, approximately every 5 seconds.

## MQTT

- Broker: `127.0.0.1`
- Port: `8883`
- Transport: MQTT over TLS
- Topic: `securebox/sensors`
- QoS: `1`
- Delivery meaning: at least once. Duplicate messages are possible and are delivered at least once.
- Client ID: `securebox-beagle`
- Authentication: none enabled in the current local demo (`allow_anonymous true`).
- Publishing interval: approximately every 5 seconds.

QoS values:

| QoS | Delivery guarantee | Current setting |
|---|---|---|
| 0 | At most once | No retry or acknowledgement |
| 1 | At least once | Current setting |
| 2 | Exactly once | Available, more network overhead |

## TLS certificates

Generated by `firmware_beagley_ai/setup_mqtt_tls.sh`:

- CA certificate: `/etc/mosquitto/certs/securebox/ca.crt`
- CA private key: removed from the board after setup
- Broker certificate: `/etc/mosquitto/certs/securebox/server.crt`
- Broker private key: `/etc/mosquitto/certs/securebox/server.key`

The application validates the broker using the CA certificate. Current setup only proves the broker identity; it does **not** issue client certificates, so the MQTT clients are not authenticated individually.

Subscriber command:

```bash
mosquitto_sub --cafile /etc/mosquitto/certs/securebox/ca.crt \
  -h 127.0.0.1 -p 8883 -t securebox/sensors -v
```

Broker listener:

```text
127.0.0.1:8883
TLS 1.2+
```

Do not copy the CA private key or expose port 8883 publicly unless authentication and certificate handling are added.

## BMP280 voltage and resistors

- Use 3.3 V for VCC on a 3.3 V module.
- I2C SDA/SCL are 3.3 V logic.
- A normal BMP280 breakout includes required pull-up resistors; no extra resistors are normally needed.
- Never connect a 5 V powered I2C sensor directly to Beagle GPIO.
- A BMP280 does not measure humidity; the dashboard shows humidity as unavailable.
